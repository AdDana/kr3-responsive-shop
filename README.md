## Описание

Адаптивный учебный интернет-магазин коллекционных фигурок, рассчитанный на телефон, планшет и компьютер. Есть каталог с фильтрацией, страница товара, форма заявки, контакты и модальное окно быстрого заказа. Все формы демонстрационные: реальной отправки персональных данных нет.

**Происхождение:** за основу взят HTML/CSS-проект [КР №1](https://github.com/AdDana/kr1-html-css-shop), как требуют методические указания. Тематика магазина и наполнение согласованы с [КР №2](https://github.com/AdDana/kr2-bootstrap-shop). Bootstrap не используется: разметка страниц товара и заказа реализована самостоятельно на CSS Grid/Flexbox.

## Адаптивные решения

1. На **всех пяти страницах** указан `viewport`. Файл `responsive.css` подключён **после** `style.css`.
2. Mobile First и медиазапросы с `min-width: 640px`, `768px`, `960px`, `1050px`, `1160px`. Для раскладки используются CSS Grid и Flexbox без фреймворков.
3. Навигация: на телефоне кнопка «Меню», на планшете и компьютере горизонтальные ссылки; состояние раскрытия доступно через `aria-expanded`, клавиша Escape закрывает меню.
4. Hero: плавный внутренний отступ и размер заголовка (`clamp`), адаптивное фоновое изображение с полупрозрачным слоем для читаемости текста.
5. Карточки: одна колонка на телефоне, две с 640 px, три с 1050 px. Применены `minmax(0, 1fr)`, `min-width: 0` для защиты от переполнения.
6. Каталог: мобильные фильтры раскрываются через нативный `details`; на десктопе они открыты и расположены рядом с товарами. Работают фильтры по подборке и примерной цене в рублях, сброс и сообщение при отсутствии товаров.
7. Страница товара: фото и описание в одной колонке на телефоне, в двух на планшете и компьютере. Таблица характеристик до 639 px становится набором удобных карточек; на больших ширинах — обычная таблица.
8. Формы заказа и обратной связи: одна колонка на телефоне и две с 768 px, крупные интерактивные поля, переносимые кнопки, валидация.
9. Диалог быстрого заказа ограничен размерами экрана, прокручивается по вертикали, закрывается кнопкой, Escape и нажатием на затемнение.

### Изображения без смещения

- Для каждой карточки используется контейнер `picture` с постоянным `aspect-ratio: 5 / 6`.
- У изображений `max-width: 100%`, `height: auto` (общая защита) и внутри медиаконтейнеров `width: 100%`, `height: 100%`, `object-fit: contain`, `object-position: center`: фигурка **не обрезается и не выходит за границы**.
- Для каталога и главной созданы отдельные файлы WebP шириной 320 и 640 пикселей, для главной фотографии товара дополнительно 960 px.
- `picture > source` использует `srcset` и `sizes`; `img` содержит JPG-fallback, осмысленный `alt`, исходные размеры (`width`/`height`), а карточки — ленивую загрузку (`loading="lazy"`).
- Изображения локальные: сайт остаётся целостным без внешних сервисов изображений.

## Доступность

- Ссылка «Перейти к содержимому» в начале каждой страницы (skip-link).
- По одному `h1` на страницу, логичная последовательность разделов `h2`/`h3`, семантические `header`/`nav`/`main`/`section`/`footer`.
- Видимый клавиатурный `:focus-visible` и усиленный контраст текста, ссылок и кнопок.
- У всех изображений описания `alt`.
- У форм явно подписанные поля (`label`), обязательные поля помечаются, ошибки получают `aria-invalid` и фокус.
- У статусов отправки/фильтрации `role="status"` и `aria-live="polite"`.
- Модальное окно использует нативный `<dialog>` с ловушкой фокуса и закрытием по Escape.
- Учтено `prefers-reduced-motion`.

## Контрольные ширины и проверки

| Ширина | Назначение | Сетка товаров | Каталог |
|---|---|---|---|
| 360 px | обычный телефон | 1 колонка | фильтры над товарами, свёрнуты |
| 430 px | крупный телефон | 1 колонка | фильтры над товарами, свёрнуты |
| 768 px | планшет | 2 колонки | фильтры над товарами |
| 1024 px | небольшой компьютер | 2 колонки | боковые фильтры + товары |
| 1440 px | широкий компьютер | 3 колонки | боковые фильтры + товары |

`tests/responsive.mjs` автоматически обходит **все пять страниц на каждой из пяти ширин** (25 состояний) и проверяет:

- горизонтальное переполнение всей страницы;
- загрузку изображений и выход изображений за контейнеры;
- сохранение `object-fit: contain`;
- мобильное меню и Escape, фильтрацию и сброс, открытие/закрытие диалога, заполнение формы;
- делает PNG-скриншоты основных страниц на 360, 768 и 1440 px в `tests/screenshots/`.

Статическая проверка `tests/static_check.py` проверяет разметку, ссылки, ресурсы и подключение CSS. Она была выполнена в среде подготовки проекта. **Полноценный визуальный тест Chromium и Lighthouse здесь выполнить не удалось из-за отсутствия доступного браузера**; они запускаются локально или в GitHub Actions после загрузки проекта.

## Как запустить и проверить

Сам сайт статический: откройте `index.html` или запустите локальный сервер:

```bash
python3 -m http.server 8000
```

Проверки (требуются Node.js 22+, Python 3 и Chromium для Lighthouse):

```bash
npm install
npx playwright install chromium
npm run test:static
npm run test:responsive
npm run audit
```

## Lighthouse

Скрипт `npm run audit` проверяет **Accessibility** для `index.html`, `catalog.html`, `order.html` и сохраняет отчёты:

- `lighthouse/accessibility-index.html`
- `lighthouse/accessibility-catalog.html`
- `lighthouse/accessibility-order.html`

Такие же проверки запускает workflow `.github/workflows/quality.yml`; он прикладывает отчёты и скриншоты как артефакт GitHub Actions. Для сдачи по методическим указаниям нужно **скачать полученные отчёты, поместить в `lighthouse/` и закоммитить**. Не следует указывать оценку Lighthouse до реального запуска.
